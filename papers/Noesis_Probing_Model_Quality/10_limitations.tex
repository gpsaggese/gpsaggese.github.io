\section{Limitations and future work}
\label{sec:limitations}

The following limitations follow from the design or from the code at the
described commit. Each lists a possible direction.

\begin{enumerate}
  \item \textbf{No live evidence.} The calibration has not been run, so the
    survivor count, the per-target accuracies, and the real detection rates are
    unknown (Section~\ref{sec:status}). The activation threshold of 150 may
    prove binding (Section~\ref{sec:calibration_analysis}).
  \item \textbf{Recognizable prompts.} The bank is stored in a version-controlled
    repository and regenerated by a deterministic script, and the prompts are
    templated and end with fixed format instructions. A seller with access to
    either could recognize canary prompts and serve them with a stronger model,
    which would defeat property P3 in practice even though the request carries no
    marker. Directions include a private bank, per-contract fresh generation
    from the key, paraphrase, and prompts drawn from the distribution of real
    traffic.
  \item \textbf{Request shape.} Probes use temperature $0$, at most 64 output
    tokens, and short prompts. Buyer traffic can differ in all three, so the
    distribution of the request itself can reveal a probe.
  \item \textbf{Strict output format.} Exact-match grading couples correctness
    with format compliance (Section~\ref{sec:grading}). A model that answers
    correctly in prose is graded $0$, and this can confound a capability
    comparison across models with different instruction-following habits.
  \item \textbf{One weak model.} Calibration discriminates against a single weak
    model. The retained canaries can be easy for other substitutes, such as a
    quantized copy of the contracted model, and the detection analysis
    (Section~\ref{sec:detection_power}) shows that small shortfalls need many
    probes.
  \item \textbf{Correlated repetitions.} With temperature $0$ the three
    repetitions at a target are expected to be highly correlated, so the
    independence assumption in Proposition~\ref{prop:acceptance} is
    optimistic. Calibration at a positive temperature, or with paraphrased
    prompts, would give more independent samples.
  \item \textbf{Schedule state.} The schedule is recomputed from the currently
    active canaries on every pass, and only claimed slots are persisted. A
    change of the active set during a window would change later slots. After a
    worker outage, all overdue slots become due and run in succession, which
    breaks the spacing guarantee of Proposition~\ref{prop:spacing}. Persisting
    the full schedule when a contract becomes active would remove both effects.
  \item \textbf{Stuck probes and throughput.} A probe left \texttt{RUNNING} by a
    crashed worker is not reclaimed, and probes execute sequentially within a
    pass, so a slow provider can delay other contracts by up to its timeout. A
    lease with expiry and bounded concurrency are natural remedies. The request
    row and the probe completion are written in separate statements, so a crash
    between them leaves a graded request attached to a probe that stays
    \texttt{RUNNING}.
  \item \textbf{Non-cryptographic generator.} Selection seeds Python's
    Mersenne Twister generator with a keyed hash. The output of the shuffles
    that an observer sees is a small sample, and state recovery from it is
    unlikely, but a construction that derives each choice directly from the
    keyed hash would remove the question.
  \item \textbf{Binary quality and no tier mapping.} The white paper's capability
    tiers are not implemented. Quality is a single accuracy threshold
    $\qminattr$ on exact-match canaries, and there is no mapping from accuracy to a
    tier $\hat c(x)$.
  \item \textbf{Two tests per contract.} The union bound of
    Section~\ref{sec:verdict_rule} allows a false-failure probability of about
    twice the nominal level for a seller exactly at both promises, and the
    Wilson bound is slightly liberal at the sample sizes in use. A sequential
    test would allow early stopping, and a corrected bound would restore the
    nominal level.
  \item \textbf{Unverified database properties.} The PostgreSQL-backed tests
    were skipped in the validation run (Section~\ref{sec:tests}).
\end{enumerate}
