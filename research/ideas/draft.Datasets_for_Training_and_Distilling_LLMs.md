## Core Idea
- Several ideas in this directory require actually training a small LM
  ([[draft.Create_a_Small_Large_Language_Model_for_Python]],

  [[draft.Create_a_Small_Large_Language_Model_for_Logic]],
  [[draft.Train_LLM_on_simple_language]]), and each one currently re-derives its
  own answer to "which corpus, and how do I get it"
- Build one shared, practical map of the data landscape: what corpora exist for
  pre-training (Wikipedia dumps, Common Crawl and its cleaned derivatives), and
  what prompt/completion datasets exist for distilling a large model into a
  small one
- The useful output is not a link list but a comparison with the properties that
  actually decide a project: size in tokens, license, cleaning already applied,
  download/storage cost, and the preprocessing pipeline needed to make it usable
  on a lab-scale budget

## Key Examples
- **Pre-training, curated**: Wikipedia dumps, Project Gutenberg, ArXiv: small,
  clean, permissively licensed, good for a first end-to-end run
- **Pre-training, web scale**: Common Crawl and its cleaned derivatives (C4,
  RefinedWeb, FineWeb, The Pile, Dolma): the practical question is how much of
  the quality gap is the raw data vs. the filtering pipeline applied to it
- **Distillation**: instruction/completion sets generated by a teacher model
  (Alpaca-style self-instruct, OpenOrca, UltraChat, OpenHermes), plus
  logged prompt/response pairs from a self-hosted gateway as in
  [[draft.Clone_openrouter]]
- **Failure mode**: a corpus is nominally huge but its license or its
  benchmark-contamination profile makes any capability claim from it
  unpublishable

## Questions
1. At the scale these projects can afford (single-GPU to small-cluster), does
   data quality or data quantity bind first: is a small curated corpus
   competitive with a filtered web slice at matched compute?
2. How much of the deduplication/filtering work is already done in the public
   derivatives, and how much has to be redone per project?
3. For distillation, is teacher-generated data on the target task distribution
   better than a large generic instruction set of the same token count?

## Research Topics
- Inventory and comparison table: tokens, license, cleaning, access mechanism,
  storage footprint
- Deduplication and quality-filtering pipelines (MinHash/LSH dedup, classifier
  filtering, perplexity filtering) and their measured effect
- Benchmark contamination checks before any evaluation claim
- Streaming/sharded loading so a corpus larger than local disk is still usable

## Implementation plan

- Milestone 1: build the corpus comparison table
  - Survey pre-training corpora: Wikipedia dumps, Project Gutenberg, ArXiv,
    and the Common Crawl derivatives (C4, RefinedWeb, FineWeb, The Pile,
    Dolma)
  - Survey distillation sets: Alpaca-style self-instruct, OpenOrca, UltraChat,
    OpenHermes, and logged prompt/response pairs from
    [[draft.Clone_openrouter]]
  - For each corpus, record tokens, license, cleaning already applied, access
    mechanism, storage footprint, and known contamination issues
  - This is the result: a comparison table covering every candidate corpus,
    checked into this idea's directory

- Milestone 2: build a reusable preprocessing pipeline
  - Pick one curated corpus (e.g. Wikipedia) and one web-derived slice (e.g.
    FineWeb) as the pilot pair
  - Implement a streaming/sharded loader so neither corpus needs to fit on
    local disk at once
  - Implement deduplication (MinHash/LSH) and quality filtering (classifier or
    perplexity threshold), and measure how much each step removes
  - This is the result: a script (or `invoke` task) that turns either raw
    corpus into tokenized, deduped shards end-to-end

- Milestone 3: check benchmark contamination and compare distillation sources
  - Run an n-gram overlap check between the two pilot corpora and the test
    sets of the benchmarks the dependent small-LM ideas plan to report
  - Assemble one teacher-generated distillation sample on a target task and
    compare it against a generic instruction set of matched token count
  - This is the result: a contamination report for both pilot corpora, plus a
    documented, justified choice of distillation source

- Milestone 4: wire the shared data path into the dependent ideas
  - Point each dependent idea at the pipeline from Milestone 2:
    - [[draft.Create_a_Small_Large_Language_Model_for_Python]]
    - [[draft.Create_a_Small_Large_Language_Model_for_Kids_Book]]
    - [[draft.Create_a_Small_Large_Language_Model_for_Logic]]
    - [[draft.Train_LLM_on_simple_language]]
  - Summarize the quality-vs-quantity and dedup-redundancy findings from
    Milestones 2 and 3 against the Questions section
  - This is the result: one shared, documented data-loading path referenced by
    name in every dependent idea file
