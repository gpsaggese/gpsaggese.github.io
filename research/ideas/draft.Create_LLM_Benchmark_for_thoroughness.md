# Benchmark for LLM Thoroughness on Multi-Site Tasks

## Status

- **Status:**: draft
- **Complete Specs:**: 30%

## Core Idea

- When a prompt asks for many things at once, or asks for one rule to be applied
  everywhere it applies, an LLM typically does part of the work and reports the task
  as complete
- This is structurally similar to needle-in-a-haystack, with one difference that
  changes the measurement:
  - Needle-in-a-haystack: one target, scored as hit or miss
  - Thoroughness: $N$ targets, scored as recall over all of them
- Hypothesis: recall decays with the number of applicable sites $N$ and with document
  length $L$
  - The decay is steeper than for single-target retrieval
  - Reason: no salience signal tells the model when to stop
- The benchmark is cheap to build because ground truth can be generated by
  construction: inject $N$ known violations into a document, then measure how many
  the model finds and fixes

## Formalization

- Let $D$ be a document, $r$ a rule, and $S(D, r)$ the set of sites in $D$ where $r$
  applies, known by construction
- Let $\hat{S}$ be the set of sites the model acts on
- Thoroughness is recall over applicable sites:

  ```text
  T(N, L) = E[ |intersect(S, S_hat)| / |S| ]
  ```

- False-positive rate guards against the degenerate "rewrite everything" strategy:

  ```text
  FP = |setdiff(S_hat, S)| / |S_hat|
  ```

- Report the pair, or a single $F_1$, as a function of the two stress axes:
  - $N$: number of applicable sites
  - $L$: document length, holding $N$ fixed (dilution)
- Iterated application measures whether the gap closes with repetition:

  ```text
  T_m = recall after m sequential passes over the same document
  ```

  - If $T_m \to 1$, thoroughness is a scheduling problem solvable by looping
  - If $T_m$ saturates below 1, some sites are systematically invisible

## Key Examples

- **Rule application over a codebase**: apply `.claude/skills/coding.rules.md` to a
  file with 20 known violations and count how many are fixed in one pass
- **Multi-instruction prompt**: a single prompt containing 15 independent requested
  edits, scored by how many are present in the output
- **Dilution control**: hold $N = 10$ fixed and grow the document from 200 to 5000
  lines to isolate length from site count
- **Failure mode**: the model finds the first and last few sites and skips the
  middle, so the position histogram of misses is not uniform
- **Degenerate strategy**: a model that flags every line reaches recall 1 with
  useless precision, which is why $FP$ must be reported alongside $T$

## Questions

1. Is the drop-off in $T(N)$ driven by output budget (the model stops when the answer
   gets long) or by attention (it never located the sites)? A test: ask only to
   _list_ the sites, not to fix them, and compare recall
2. Do models that self-report "all instances fixed" have calibrated confidence, or is
   the claim of completeness uncorrelated with actual recall?
3. Does an externalized loop (find all sites, then fix one at a time) recover recall
   to near 1? See `draft.Create_script_to_apply_prompt_in_chunks.md`
4. If thoroughness is the binding constraint rather than capability, agent
   evaluations that score single-shot output are measuring the wrong thing

## Research Topics

- **Benchmark construction**: synthetic injection of violations into real documents,
  using rule sets that admit deterministic ground truth
- **Stress axes**: separating $N$, $L$, and rule complexity, plus the position
  histogram of misses
- **Model comparison**: run the same suite across models and reasoning-effort levels,
  and check whether thoroughness tracks general capability rankings or is a separate
  axis
- **Mitigations**: chunking, enumerate-then-act decomposition, and self-verification
  passes, each scored on the same curve
- **Calibration**: correlation between self-reported completion and measured recall
- **Relation to compliance**: thoroughness is recall for one rule over many sites,
  compliance is recall over many rules, see `draft.How_to_measure_LLM_compliance.md`

## Implementation plan

- Milestone 1: build the generator and scorer
  - Pick 3-5 rules with deterministic checkers from an existing rule set
  - Write a generator injecting $N$ violations at known positions into a document of
    controlled length $L$
  - Write a scorer computing recall, false positives, and the miss-position histogram
  - This is the result: a parameterized benchmark generator with a reproducible seed
- Milestone 2: measure the decay surface
  - Sweep $N$ and $L$ on a grid for one model
  - This is the result: $T(N, L)$ with confidence intervals plus the miss-position
    histogram
- Milestone 3: compare models and diagnose the cause
  - Run the suite across models and across list-only vs fix modes
  - This is the result: a thoroughness leaderboard plus evidence on whether the
    bottleneck is retrieval or output budget
- Milestone 4: test mitigations
  - Compare single-pass, iterated-pass, and externally driven loop strategies at
    equal token cost
  - This is the result: a recommendation on the cheapest strategy reaching recall
    close to 1
