# Design: Pipeline

## Goal

- Run the stages of the pipeline as one executable per stage, linked only by files
  on disk, and run all of them in order with a shell script
  ([`D26`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d26-the-resolver-is-a-separate-executable-that-reads-and-writes-csv),
  [`D27`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d27-the-pipeline-is-split-into-one-executable-per-stage))
  - Parse and check the CLI flags of its stage, call the other components
  - Loop on the papers, and turn a failure of one paper into an `Issue`, so the run
    goes on (PRD
    [`R5`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r5-unresolved-or-ambiguous-line),
    [`R10`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r10-failed-download-or-conversion))
  - Skip the work that a previous run already did
    ([`R11`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r11-rerun-skips-converted-papers),
    [`R17`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r17-rerun-skips-extraction))
- The stages, in order:

  | Executable            | Stage    | Reads                                          | Writes                                                                |
  | :-------------------- | :------- | :--------------------------------------------- | :-------------------------------------------------------------------- |
  | `resolve_papers.py`   | resolve  | Input CSV                                      | Papers CSV, issues CSV                                                |
  | `download_papers.py`  | download | Papers CSV                                     | `papers/<BASE>.pdf`, `papers/<BASE>.md`, `state/issues.download.json` |
  | `extract_features.py` | extract  | Papers CSV, PDF, markdown                      | `papers/<BASE>.features.json`, `state/issues.extract.json`            |
  | `report_papers.py`    | rate     | Papers CSV, features files                     | `papers/<BASE>.rating.json`, `state/issues.rate.json`                 |
  | `report_papers.py`    | report   | Papers CSV, issues CSV, features, rating files | `references.md`, `report.csv`, `issues.csv`                           |

- Where it fits: user -> `pipeline` -> `fetcher`, `bib_sources`, `report`; the
  scripts also hold the code of `resolver` (`resolve_papers.py`), `extractor`
  (`extract_features.py`), and `rater` (`report_papers.py`), per
  [`D28`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d28-a-module-with-one-caller-lives-in-that-script)
- Overview:
  [`research/Estimate_academic_paper_quality/docs/02-design.architecture.md`](/research/Estimate_academic_paper_quality/docs/02-design.architecture.md)
- Decisions:
  [`research/Estimate_academic_paper_quality/docs/03-decisions.md`](/research/Estimate_academic_paper_quality/docs/03-decisions.md)

## Files

- [`research/Estimate_academic_paper_quality/resolve_papers.py`](/research/Estimate_academic_paper_quality/resolve_papers.py):
  the executable of the resolver, `_parse()` and `_main(parser)` per
  [`.claude/skills/script.rules.md`](/.claude/skills/script.rules.md), and the
  private `_read_input_lines()` and `_resolve()`, and the code of `resolver`
  ([`02.2-design.resolver.md`](/research/Estimate_academic_paper_quality/docs/02.2-design.resolver.md))
- [`research/Estimate_academic_paper_quality/download_papers.py`](/research/Estimate_academic_paper_quality/download_papers.py):
  the executable of the stage `download`, with the private `_download()`
- [`research/Estimate_academic_paper_quality/extract_features.py`](/research/Estimate_academic_paper_quality/extract_features.py):
  the executable of the stage `extract`, with the private `_ExtractConfig`,
  `_make_llm_func()`, `_extract_paper()`, and `_extract()`, and the code of
  `extractor`
  ([`02.5-design.extractor.md`](/research/Estimate_academic_paper_quality/docs/02.5-design.extractor.md))
- [`research/Estimate_academic_paper_quality/report_papers.py`](/research/Estimate_academic_paper_quality/report_papers.py):
  the executable of the stages `rate` and `report`, with the private `_load_tiers()`,
  `_rate_paper()`, `_rate()`, `_read_paper_files()`, and `_report()`, and the code of
  `rater`
  ([`02.6-design.rater.md`](/research/Estimate_academic_paper_quality/docs/02.6-design.rater.md))
- [`research/Estimate_academic_paper_quality/estimate_paper_quality.sh`](/research/Estimate_academic_paper_quality/estimate_paper_quality.sh):
  runs the four executables in order
- [`research/Estimate_academic_paper_quality/epq_paths.py`](/research/Estimate_academic_paper_quality/epq_paths.py):
  the one place that names the files that the executables share
- [`research/Estimate_academic_paper_quality/epq_issues.py`](/research/Estimate_academic_paper_quality/epq_issues.py):
  `make_paper_issue()` and `get_last_line()`, used by the loop of each stage

## Import Graph

- A script imports only `epq_*` modules and `helpers`, never another script: the
  scripts talk through files, so a stage runs alone on the output of an earlier run
- Each script imports the modules of its stage, plus `epq_report`, `epq_issues`,
  `epq_paths`, and `epq_types`
  - `resolve_papers.py`: `epq_bib_sources`, `epq_fetcher`
  - `download_papers.py`: `epq_fetcher`
  - `extract_features.py`: `epq_fetcher`,
    [`helpers.hllm`](/helpers_root/helpers/hllm.py) (imported inside
    `_make_llm_func()`), and
    [`helpers.hllm_cost`](/helpers_root/helpers/hllm_cost.py)
  - `report_papers.py`: `epq_bib_sources`,
    [`helpers.hselect_action`](/helpers_root/helpers/hselect_action.py), and
    [`helpers.hcache_simple`](/helpers_root/helpers/hcache_simple.py)
- A test of the import graph fails on a script that imports another script

## External Code

- [`helpers_root/dev_scripts_helpers/download/download_academic_paper_to_md.py`](/helpers_root/dev_scripts_helpers/download/download_academic_paper_to_md.py)
  uses the same [`hselect_action`](/helpers_root/helpers/hselect_action.py) pattern
  (`_VALID_ACTIONS`, `_DEFAULT_ACTIONS`, `mark_action()`), so `report_papers.py`
  follows it
- Each executable has a `uv run` header with its own dependencies, so a stage does
  not install what another stage needs (e.g., `report_papers.py` has no `pymupdf` and
  no `openai`)

## One Request End to End

- `resolve_papers._main()`:
  - Checks at the boundary that `--input` exists, and sets the cache dir of
    [`hcache_simple`](/helpers_root/helpers/hcache_simple.py) to `--cache_dir`
  - Reads the column `input` with `_read_input_lines()`, which calls
    `epq_report.read_input_csv()` and `_parse_line()`
  - `_resolve(input_csv, papers_csv, issues_csv, sources)` calls
    `_resolve_line()` for each line inside a `try` (the catch of D21, so a
    failed lookup is an `unresolved` issue), then `_finalize_papers()`
  - Writes the papers CSV and the issues CSV with `epq_report`
  - With `--dry_run`, only logs the kind of each row
- `download_papers._main()` checks that the papers CSV exists, then
  `_download(papers, output_dir, ...)`:
  - For each paper: skips it if `epq_fetcher.is_fetched()` is true
    ([`R11`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r11-rerun-skips-converted-papers))
  - Else calls `epq_fetcher.fetch_paper()` and turns a failed `FetchResult` into an
    `Issue` with status `no_download_link`, `download_failed`, or `conversion_failed`
  - Writes `state/issues.download.json`
  - With `--dry_run`, only logs the papers to download
- `extract_features._main()` checks that the papers CSV and `papers/` exist, builds
  the LLM function, then `_extract(papers, config, ...)`, for each paper:
  - Skips it if it has no markdown (the download issue already says why)
  - Skips it if its features file exists and `--force_extract` is not set
    ([`R17`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r17-rerun-skips-extraction))
  - Reads the markdown and the text of each PDF page with `epq_fetcher`, and counts
    the pages
  - Calls `_extract_features()` with an injected LLM function
  - Builds the Recency feature from the year of the record, with the name of the
    source as evidence
  - Writes `papers/<BASE>.features.json` with `epq_report`: the features, the facts,
    the affiliations, the page count, and the provenance, but no rating
  - Logs the LLM cost of the paper and, at the end, the total
  - Writes `state/issues.extract.json`
  - With `--dry_run`, only logs the papers to extract
- `report_papers._main()` checks that the papers CSV exists, and that
  `--resolve_issues` exists if it is set, then runs the selected actions in this order:
  `rate`, `report`
  - Without `--resolve_issues`, uses the issues CSV next to the papers CSV
    (`papers.csv` gives `papers.issues.csv`) if it exists, and logs a warning if not
  - Action `rate`: `_rate(papers, output_dir, ...)`, for each paper with a features file:
    - Reads the features file and calls `epq_bib_sources.get_citation_count()`, with
      `refresh=True` when `--refresh_citations` is set, so the count is fresh
    - Calls `_compute_rating()` with the page count and the affiliations of the
      features file, the citation count, the year of the paper, and today
    - Writes `papers/<BASE>.rating.json` with `epq_report`
    - Rates every paper at each run, since a new tier list or a new citation count
      changes the rating, and a rating costs no LLM call
    - Writes `state/issues.rate.json`
  - Action `report`: `_report(papers, output_dir, ...)`
    - Reads the issues CSV of the resolver, the issues of the stages `download`,
      `extract`, and `rate`, the features files, and the rating files
    - A paper with a features file and no rating file is an issue with status
      `rating_missing`, unless the stage `rate` already reported it
    - Writes `references.md`, `report.csv`, and `issues.csv`
    - A stage that is not selected is not needed: the output of an earlier run is read
      from `<output_dir>`
      ([`D18`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d18-all-the-state-lives-in-the-output-dir))
  - With `--dry_run`, only logs the papers to rate and the files to write
- `estimate_paper_quality.sh -i INPUT_CSV -o OUTPUT_DIR` runs, in this order,
  `resolve_papers.py`, `download_papers.py`, `extract_features.py`, and
  `report_papers.py`, forwards `-v` to each one, and stops at the first one that
  fails
  - It puts the papers CSV at `<OUTPUT_DIR>/papers.csv`, and the cache of the
    resolver at `<OUTPUT_DIR>/state/cache`
  - It adds the repo root and `helpers_root` to `PYTHONPATH`
  - A rerun on the same `OUTPUT_DIR` repeats only the work that is not done
- Error handling
  ([`D21`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d21-the-loop-of-each-stage-catches-errors-per-paper)):
  - The inner modules assert with `hdbg.dassert_*` and raise
  - The loop of each stage catches `Exception` per paper and records an `Issue` with
    the last line of the message as the reason
  - An error outside the loop (e.g., a bad flag, a full disk) stops the script
- Idempotence: each stage can run twice with the same result, and no stage reads the
  return value of another stage

## Configuration, Interfaces, and Known Limits

- Configuration: `extract_features.py` bundles its options in a private frozen
  dataclass; the other scripts pass their few options as keyword arguments
  ```python
  @dataclasses.dataclass(frozen=True)
  class _ExtractConfig:
      # Dir of all the outputs of the run.
      output_dir: str
      # LLM, "" for the default model of `helpers.hllm`.
      model: str
      force_extract: bool
      # Max chars of markdown sent to the LLM (D13).
      max_chars: int
      dry_run: bool
  ```
- Interfaces: CLI flags

  | Script                | Flag                                                            | Default       | Meaning                                                                                                                                                                                 |
  | :-------------------- | :-------------------------------------------------------------- | :------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | `resolve_papers.py`   | `-i`, `--input`                                                 | required      | Input CSV with a column `input`                                                                                                                                                         |
  | `resolve_papers.py`   | `-o`, `--output`                                                | required      | Papers CSV to write                                                                                                                                                                     |
  | `resolve_papers.py`   | `--issues_output`                                               | `""`          | Issues CSV to write; empty is the papers CSV with `.issues.csv`                                                                                                                         |
  | `resolve_papers.py`   | `--cache_dir`                                                   | `""`          | Cache of the API answers; empty is `cache/` next to the papers CSV                                                                                                                      |
  | `resolve_papers.py`   | `--email`                                                       | `""`          | Contact email for Unpaywall; empty skips Unpaywall                                                                                                                                      |
  | `resolve_papers.py`   | `--dry_run`                                                     | off           | Show how each row is classified, with no lookup and no output                                                                                                                           |
  | `download_papers.py`  | `-i`, `--input`                                                 | required      | Papers CSV that `resolve_papers.py` wrote ([`D26`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d26-the-resolver-is-a-separate-executable-that-reads-and-writes-csv)) |
  | `download_papers.py`  | `--output_dir`                                                  | required      | Dir of all outputs and state ([`D10`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d10-the-user-gives-the-output-dir))                                                |
  | `download_papers.py`  | `--dry_run`                                                     | off           | Show the papers to download, with no download and no output                                                                                                                             |
  | `extract_features.py` | `-i`, `--input`, `--output_dir`                                 | required      | Same as `download_papers.py`                                                                                                                                                            |
  | `extract_features.py` | `--model`                                                       | `""`          | LLM to call; empty is the default of `helpers.hllm`                                                                                                                                     |
  | `extract_features.py` | `--force_extract`                                               | off           | Extract again the papers that have a features file                                                                                                                                      |
  | `extract_features.py` | `--max_chars`                                                   | `300000`      | Cap on the markdown sent to the LLM                                                                                                                                                     |
  | `extract_features.py` | `--dry_run`                                                     | off           | Show the papers to extract, with no LLM call and no output                                                                                                                              |
  | `report_papers.py`    | `-i`, `--input`, `--output_dir`                                 | required      | Same as `download_papers.py`                                                                                                                                                            |
  | `report_papers.py`    | `--resolve_issues`                                              | `""`          | Issues CSV that `resolve_papers.py` wrote; empty is the papers CSV with `.issues.csv`, if it exists                                                                                     |
  | `report_papers.py`    | `--refresh_citations`                                           | off           | Ask for fresh citation counts in the action `rate`                                                                                                                                      |
  | `report_papers.py`    | `--cache_mode`                                                  | `""`          | `REFRESH_CACHE` refetches the citation counts                                                                                                                                           |
  | `report_papers.py`    | `--action`, `--skip_action`, `--clear_actions`, `--all_actions` | `rate,report` | Stage selection                                                                                                                                                                         |
  | `report_papers.py`    | `--dry_run`                                                     | off           | Show the papers to rate and the files to write, with no lookup and no output                                                                                                            |
  | all                   | `-v`                                                            | `INFO`        | Log level                                                                                                                                                                               |

- Flags of `estimate_paper_quality.sh`: `-i INPUT_CSV` and `-o OUTPUT_DIR` (required),
  `-m MODEL`, `-v LOG_LEVEL`, `-f` (extract again), `-r` (fresh citation counts), and
  `-h`
- Known limits:
  - Sequential: one paper at a time
  - A rerun must use the same `--output_dir`
  - A paper removed from the input list keeps its files in `papers/`, but leaves the
    report
  - `--dry_run` does not chain: a later stage needs the files of the earlier stages,
    which a dry run does not write, so the shell script has no dry run

## Deliberately Not Built

- A config file: the flags are few
- A Python script that runs all the stages (e.g., `--all_actions`): it would mix
  stages with different dependencies, runtimes, and schedules, see
  [`D27`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d27-the-pipeline-is-split-into-one-executable-per-stage)
- Parallel stages, retries of a failed paper in the same run: a rerun retries it
