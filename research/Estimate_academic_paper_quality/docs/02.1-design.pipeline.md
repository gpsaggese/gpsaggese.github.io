# Design: Pipeline

## Goal

- Run the stages of the pipeline as one executable per stage, linked only by files
  on disk, and run all of them in order with a Python script that calls them as
  subprocesses
  ([`D26`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d26-the-resolver-is-a-separate-executable-that-reads-and-writes-csv),
  [`D27`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d27-the-pipeline-is-split-into-one-executable-per-stage),
  [`D32`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d32-the-pipeline-script-is-python-and-runs-the-stages-as-subprocesses))
  - Parse and check the CLI flags of its stage, call the other components
  - Loop on the papers, and turn a failure of one paper into an `Issue`, so the run
    goes on (PRD
    [`R5`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r5-unresolved-or-ambiguous-line),
    [`R10`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r10-failed-download-or-conversion))
  - Skip the work that a previous run already did
    ([`R11`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r11-rerun-skips-converted-papers),
    [`R17`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r17-rerun-skips-extraction))
- The stages, in order:

  | Executable            | Stage    | Reads                                             | Writes                                                                      |
  | :-------------------- | :------- | :------------------------------------------------ | :-------------------------------------------------------------------------- |
  | `resolve_papers.py`   | resolve  | Input CSV                                         | `00-paper_list.csv`, `01-resolve.paper_list.json`, `01-resolve.issues.json` |
  | `download_papers.py`  | download | Papers file                                       | `papers/<BASE>.pdf`, `papers/<BASE>.md`, `02-download.issues.json`          |
  | `extract_features.py` | extract  | Papers file, PDF, markdown                        | `papers/<BASE>.features.json`, `03-extract.issues.json`                     |
  | `report_papers.py`    | rate     | Papers file, features files                       | `papers/<BASE>.rating.json`, `04-rate.issues.json`                          |
  | `report_papers.py`    | report   | Papers file, issues files, features, rating files | `04-report.references.md`, `04-report.report.csv`, `04-report.issues.csv`   |

- Where it fits: user -> `pipeline` -> `fetcher`, `bib_sources`, `report`; the
  scripts also hold the code of `resolver` (`resolve_papers.py`), `extractor`
  (`extract_features.py`), and `rater` (`report_papers.py`), per
  [`D28`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d28-a-module-with-one-caller-lives-in-that-script)
- Overview:
  [`research/Estimate_academic_paper_quality/docs/02-design.architecture.md`](/research/Estimate_academic_paper_quality/docs/02-design.architecture.md)
- Decisions:
  [`research/Estimate_academic_paper_quality/docs/03-decisions.md`](/research/Estimate_academic_paper_quality/docs/03-decisions.md)

## Output Dir

- This is the source of truth for the layout of `--output_dir`; the code names the
  files in
  [`research/Estimate_academic_paper_quality/epq_paths.py`](/research/Estimate_academic_paper_quality/epq_paths.py)
- A file that a stage writes is named `NN-<stage>.<what>.<ext>`, where `NN` is the
  order of the executable
  ([`D29`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d29-numbered-stage-files-in-the-output-dir))
  ```text
  <output_dir>/
      00-paper_list.csv
      01-resolve.paper_list.json
      01-resolve.issues.json
      02-download.issues.json
      03-extract.issues.json
      04-rate.issues.json
      04-report.report.csv
      04-report.issues.csv
      04-report.references.md
      papers/
          <BASE>.pdf
          <BASE>.md
          <BASE>.features.json
          <BASE>.rating.json
      state/
          cache/
          logs/
  ```
- The files, in the order of the pipeline:

  | File                          | Written by                              | Read by                 | Format    | Content                                                 |
  | :---------------------------- | :-------------------------------------- | :---------------------- | :-------- | :------------------------------------------------------ |
  | `00-paper_list.csv`           | `resolve_papers.py`                     | The user                | CSV       | Copy of the input, so the run keeps the list it used    |
  | `01-resolve.paper_list.json`  | `resolve_papers.py`                     | The 3 other executables | JSON      | Resolved, deduped papers, newest first                  |
  | `01-resolve.issues.json`      | `resolve_papers.py`                     | `report_papers.py`      | JSON      | Input rows that gave no paper, or an ambiguous one      |
  | `02-download.issues.json`     | `download_papers.py`                    | `report_papers.py`      | JSON      | Papers that failed to download or to convert            |
  | `03-extract.issues.json`      | `extract_features.py`                   | `report_papers.py`      | JSON      | Papers that failed to extract                           |
  | `04-rate.issues.json`         | `report_papers.py`                      | `report_papers.py`      | JSON      | Papers that failed to rate                              |
  | `04-report.report.csv`        | `report_papers.py`                      | The user                | CSV       | One row per rated paper, to sort in a spreadsheet       |
  | `04-report.issues.csv`        | `report_papers.py`                      | The user                | CSV       | The issues of every stage, by stage and line            |
  | `04-report.references.md`     | `report_papers.py`                      | The user                | Markdown  | The references of all the resolved papers               |
  | `papers/<BASE>.pdf`, `.md`    | `download_papers.py`                    | `extract_features.py`   | PDF, MD   | The paper and its conversion                            |
  | `papers/<BASE>.features.json` | `extract_features.py`                   | `report_papers.py`      | JSON      | Features, facts, affiliations, page count, and the cost |
  | `papers/<BASE>.rating.json`   | `report_papers.py`                      | `report_papers.py`      | JSON      | The rating and its three signals                        |
  | `state/cache/`                | `resolve_papers.py`, `report_papers.py` | Both                    | JSON, PDF | Cache of the HTTP answers of the lookups                |
  | `state/logs/`                 | `download_papers.py`                    | The user                | Text      | Log of the download tool for each paper                 |

- Rules behind the layout
  - `rate` and `report` are stages of one script, so both get `04`
  - The files of one paper are in `papers/` with no number: the suffix says the stage
  - JSON for a file that a program reads, CSV for a file that a person sorts
    ([`D31`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d31-json-for-the-intermediate-files))
  - `state/` holds only what is not a result of a stage: the cache and the logs
  - The user gives the dir, and the executables infer every name
    ([`D30`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d30-output_dir-for-several-files-and-output-for-one))
- In the docs, `report.csv`, `issues.csv`, and `references.md` are the short names of
  the three `04-report.*` files

## Import Graph

- A script imports only `epq_*` modules and `helpers`, never another script: the
  scripts talk through files, so a stage runs alone on the output of an earlier run
- Each script imports the modules of its stage, plus `epq_report`, `epq_issues`,
  `epq_paths`, and `epq_types`
  - `resolve_papers.py`: `epq_bib_sources`, `epq_fetcher`
  - `download_papers.py`: `epq_fetcher`
  - `extract_features.py`: `epq_fetcher`,
    [`helpers.hllm_cli`](/helpers_root/helpers/hllm_cli.py)
  - `report_papers.py`: `epq_bib_sources`,
    [`helpers.hselect_action`](/helpers_root/helpers/hselect_action.py), and
    [`helpers.hcache_simple`](/helpers_root/helpers/hcache_simple.py)
- A test of the import graph fails on a script that imports another script

## External Code

- [`helpers_root/dev_scripts_helpers/download/download_academic_paper_to_md.py`](/helpers_root/dev_scripts_helpers/download/download_academic_paper_to_md.py)
  uses the same [`hselect_action`](/helpers_root/helpers/hselect_action.py) pattern
  (`_VALID_ACTIONS`, `_DEFAULT_ACTIONS`, `mark_action()`), so `report_papers.py`
  follows it
- Each executable has a `uv run` header with its own dependencies, so a stage does
  not install what another stage needs (e.g., `report_papers.py` has no `pymupdf` and
  no `llm`)

## One Request End to End

- `resolve_papers._main()`:
  - Checks at the boundary that `--input` exists, builds the paths of the output dir
    with `epq_paths`, and copies the input to `00-paper_list.csv` with
    `_copy_input()` (it skips the copy if the input is that file)
  - Sets the cache dir of
    [`hcache_simple`](/helpers_root/helpers/hcache_simple.py) to `--cache_dir`, by
    default `state/cache/` in the output dir
  - Reads the rows of the CSV with `_read_input_lines()`, which calls
    `epq_report.read_input_csv()` and `_parse_line()`
  - `_resolve(input_csv, papers_file, issues_file, sources)` calls
    `_resolve_line()` for each line inside a `try` (the catch of D21, so a
    failed lookup is an `unresolved` issue), then `_finalize_papers()`
  - Writes `01-resolve.paper_list.json` and `01-resolve.issues.json` with
    `epq_report.write_papers()` and `epq_report.write_issues()`
  - With `--dry_run`, only logs the kind of each row and the copy of the input
- `download_papers._main()` checks that the papers file exists (`--input`, by default
  `01-resolve.paper_list.json` in `--output_dir`) and that
  `0 <= --min_delay_sec <= --max_delay_sec`, then `_download(papers, output_dir, ...)`:
  - For each paper: skips it if `epq_fetcher.is_fetched()` is true
    ([`R11`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r11-rerun-skips-converted-papers))
  - Else waits a random time in `[--min_delay_sec, --max_delay_sec]`, unless it is
    the first download of the run, so the hosts do not take the script for a bot
  - Then calls `epq_fetcher.fetch_paper()` and turns a failed `FetchResult` into an
    `Issue` with status `no_download_link`, `download_failed`, or `conversion_failed`
  - Writes `02-download.issues.json`
  - With `--dry_run`, only logs the papers to download, and does not wait
- `extract_features._main()` checks that the papers file and `papers/` exist, builds
  the LLM function, then `_extract(papers, config, ...)`, for each paper:
  - Skips it if it has no markdown (the download issue already says why)
  - Skips it if its features file exists and `--force_extract` is not set
    ([`R17`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r17-rerun-skips-extraction))
  - Reads the markdown and the text of each PDF page with `epq_fetcher`, and counts
    the pages
  - Calls `_extract_features()` with an injected LLM function
  - Builds the Recency feature from the year of the record, with the name of the
    source as evidence
  - Writes `papers/<BASE>.features.json` with `epq_report`: the features, the facts,
    the affiliations, the page count, and the provenance, but no rating
  - Logs the LLM cost of the paper and, at the end, the total
  - Writes `03-extract.issues.json`
  - With `--dry_run`, only logs the papers to extract
- `report_papers._main()` checks that the papers file exists, then runs the selected
  actions in this order: `rate`, `report`
  - Action `rate`: `_rate(papers, output_dir, ...)`, for each paper with a features file:
    - Reads the features file and calls `epq_bib_sources.get_citation_count()`, with
      `refresh=True` when `--refresh_citations` is set, so the count is fresh
    - Calls `_compute_rating()` with the page count and the affiliations of the
      features file, the citation count, the year of the paper, and today
    - Writes `papers/<BASE>.rating.json` with `epq_report`
    - Rates every paper at each run, since a new tier list or a new citation count
      changes the rating, and a rating costs no LLM call
    - Writes `04-rate.issues.json`
  - Action `report`: `_report(papers, output_dir, ...)`
    - Reads the issues of the stages `resolve`, `download`, `extract`, and `rate`, the
      features files, and the rating files, all from `<output_dir>`
    - Logs a warning if `01-resolve.issues.json` does not exist, since then the issues
      file lists no unresolved line
    - A paper with a features file and no rating file is an issue with status
      `rating_missing`, unless the stage `rate` already reported it
    - Writes `04-report.references.md`, `04-report.report.csv`, and
      `04-report.issues.csv`
    - A stage that is not selected is not needed: the output of an earlier run is read
      from `<output_dir>`
      ([`D18`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d18-all-the-state-lives-in-the-output-dir))
  - With `--dry_run`, only logs the papers to rate and the files to write
- `estimate_paper_quality.py --input INPUT_CSV --output_dir OUTPUT_DIR` runs, in this
  order, `resolve_papers.py`, `download_papers.py`, `extract_features.py`, and
  `report_papers.py`, forwards `-v` to each one, and stops at the first one that
  fails
  - It has one action per executable, named after it (`resolve_papers`,
    `download_papers`, `extract_features`, and `report_papers`), selected with
    `hselect_action`: `--only_action extract_features` runs one stage on the output of
    an earlier run, and `--skip_action download_papers` skips one
    (rule `ARCH3.5`)
  - It passes `--output_dir <OUTPUT_DIR>` to every executable, and `--input` only to
    the resolver: the other three find `01-resolve.paper_list.json` in the output dir
  - It runs each executable with `hsystem.system()` and imports none of them, so the
    stages keep their own dependencies and do not share a process
  - It adds the repo root and `helpers_root` to `PYTHONPATH`
  - A rerun on the same `OUTPUT_DIR` repeats only the work that is not done
- Error handling
  ([`D21`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d21-the-loop-of-each-stage-catches-errors-per-paper)):
  - The inner modules assert with `hdbg.dassert_*` and raise
  - The loop of each stage catches `Exception` per paper and records an `Issue` with
    the last line of the message as the reason
  - An error outside the loop (e.g., a bad flag, a full disk) stops the script
- Idempotence: each stage can run twice with the same result, and no stage reads the
  return value of another stage

## Configuration, Interfaces, and Known Limits

- Configuration: `extract_features.py` bundles its options in a private frozen
  dataclass; the other scripts pass their few options as keyword arguments
  ```python
  @dataclasses.dataclass(frozen=True)
  class _ExtractConfig:
      # Dir of all the outputs of the run.
      output_dir: str
      # LLM for the `llm` library, e.g., `hllmcli.DEFAULT_MODEL`.
      model: str
      force_extract: bool
      # Max chars of markdown sent to the LLM (D13).
      max_chars: int
      dry_run: bool
  ```
- Interfaces: CLI flags

  | Script                | Flag                                                            | Default                 | Meaning                                                                                                                                                                                         |
  | :-------------------- | :-------------------------------------------------------------- | :---------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | `resolve_papers.py`   | `-i`, `--input`                                                 | required                | Input CSV with one paper per row, no header needed                                                                                                                                              |
  | `resolve_papers.py`   | `--output_dir`                                                  | required                | Dir of all outputs and state; the names of the files are inferred ([`D30`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d30-output_dir-for-several-files-and-output-for-one)) |
  | `resolve_papers.py`   | `--cache_dir`                                                   | `""`                    | Cache of the API answers; empty is `state/cache/` in the output dir                                                                                                                             |
  | `resolve_papers.py`   | `--email`                                                       | `""`                    | Contact email for Unpaywall; empty skips Unpaywall                                                                                                                                              |
  | `resolve_papers.py`   | `--dry_run`                                                     | off                     | Show how each row is classified, with no lookup and no output                                                                                                                                   |
  | `download_papers.py`  | `-i`, `--input`                                                 | `""`                    | Papers file that `resolve_papers.py` wrote; empty is `01-resolve.paper_list.json` in the output dir                                                                                             |
  | `download_papers.py`  | `--output_dir`                                                  | required                | Dir of all outputs and state ([`D10`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d10-the-user-gives-the-output-dir))                                                        |
  | `download_papers.py`  | `--min_delay_sec`                                               | `3.0`                   | Shortest random wait between two downloads                                                                                                                                                      |
  | `download_papers.py`  | `--max_delay_sec`                                               | `10.0`                  | Longest random wait between two downloads                                                                                                                                                       |
  | `download_papers.py`  | `--dry_run`                                                     | off                     | Show the papers to download, with no download, no wait, and no output                                                                                                                           |
  | `extract_features.py` | `-i`, `--input`, `--output_dir`                                 | `""`, required          | Same as `download_papers.py`                                                                                                                                                                    |
  | `extract_features.py` | `--model`                                                       | `hllmcli.DEFAULT_MODEL` | LLM to call with the `llm` library, e.g., `gpt-4o-mini`                                                                                                                                         |

  | `extract_features.py` | `--max_chars`                                                   | `300000`                | Cap on the markdown sent to the LLM                                                                                                                                                             |
  | `extract_features.py` | `--dry_run`                                                     | off                     | Show the papers to extract, with no LLM call and no output                                                                                                                                      |

  | `report_papers.py`    | `--dry_run`                                                     | off                     | Show the papers to rate and the files to write, with no lookup and no output                                                                                                                    |

- Flags of `estimate_paper_quality.py`: `--input` (required if the action `resolve_papers`
  runs) and `--output_dir` (required), `--model`, `--force_extract`,
  `--refresh_citations`, `--dry_run`, the stage selection of `hselect_action`, and
  `-v`. A flag of one stage that the script does not forward, e.g., `--email` or
  `--min_delay_sec`, needs a call of that executable
- Known limits:
  - Sequential: one paper at a time
  - A rerun must use the same `--output_dir`
  - A paper removed from the input list keeps its files in `papers/`, but leaves the
    report
  - `--dry_run` does not chain: a later stage needs the files of the earlier stages,
    which a dry run does not write, so `--dry_run` of `estimate_paper_quality.py` does
    not forward the flag: it only logs the command of each stage

## Deliberately Not Built

- A config file: the flags are few
- A Python script that runs all the stages in one process, e.g., by importing them: it
  would mix stages with different dependencies, runtimes, and schedules, see
  [`D27`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d27-the-pipeline-is-split-into-one-executable-per-stage).
  The script `estimate_paper_quality.py` runs them as subprocesses instead, see
  [`D32`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d32-the-pipeline-script-is-python-and-runs-the-stages-as-subprocesses)
- Parallel stages, retries of a failed paper in the same run: a rerun retries it

## Open Questions

   (e.g., `--max_cost_usd`)?
