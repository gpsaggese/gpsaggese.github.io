# Design: Report

## Goal

- Write and read every file that the pipeline keeps in `<output_dir>`
  - `04-report.references.md`: the normalized list of references (PRD
    [`R2`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r2-reference-format),
    [`R7`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r7-reverse-chronological-order))
  - `04-report.report.csv`: one row per paper with a features file and a rating file
    ([`R18`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r18-report-csv))
  - `04-report.issues.csv`: the unresolved lines and the failed papers, with the reason
    ([`R19`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r19-issues-csv))
  - `papers/<BASE>.features.json`: the features, the evidence, the facts, the
    affiliations, and the page count of one paper
    ([`R20`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r20-features-file)),
    also the rerun cache of `extract`
    ([`R17`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r17-rerun-skips-extraction))
  - `papers/<BASE>.rating.json`: the Paper quality rating and the three signals
    behind it, written by the action `rate` of `report_papers.py`, so that a new tier
    list needs no new extraction
    ([`D27`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d27-the-pipeline-is-split-into-one-executable-per-stage))
  - `NN-<stage>.issues.json`: the issues of the stages `resolve`, `download`,
    `extract`, and `rate`, so that each stage can run alone
  - `01-resolve.paper_list.json`: the papers of `resolve_papers.py`, and the input CSV
    that the user writes
    ([`D31`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d31-json-for-the-intermediate-files))
  - The names of all the files are in
    [`research/Estimate_academic_paper_quality/epq_paths.py`](/research/Estimate_academic_paper_quality/epq_paths.py),
    and the layout is in
    [`research/Estimate_academic_paper_quality/docs/02.1-design.pipeline.md`](/research/Estimate_academic_paper_quality/docs/02.1-design.pipeline.md)
    ([`D29`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d29-numbered-stage-files-in-the-output-dir))
- Where it fits: the four scripts -> `report` -> files
- Overview:
  [`research/Estimate_academic_paper_quality/docs/02-design.architecture.md`](/research/Estimate_academic_paper_quality/docs/02-design.architecture.md)
- Decisions:
  [`research/Estimate_academic_paper_quality/docs/03-decisions.md`](/research/Estimate_academic_paper_quality/docs/03-decisions.md)
  - The features file is JSON, read back by `report_papers.py`
    ([`D14`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d14-the-features-file-is-json-and-is-the-rerun-cache-of-extract))
  - `report.csv` has one row per paper with a features file and a rating file; the
    other papers are in `issues.csv`
    ([`D19`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d19-reportcsv-has-a-row-only-for-a-paper-with-a-features-file))
  - The normalized list also goes to `references.md`
    ([`D20`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d20-the-normalized-list-also-goes-to-referencesmd))

## One Request End to End

- `report_papers._report()` calls, in order:
  - `read_papers(path)`: the papers, already in
    [`R7`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r7-reverse-chronological-order)
    order
  - `read_issues(path)`: the issues of `resolve`, `download`, `extract`, and `rate`
  - `read_features_file()` and `read_rating_file()` for each paper that has them
  - `write_references(path, papers)`: one bullet per resolved paper, e.g.,
    ```markdown
    - 2020, Cohen et al., "Lazy Prices" (https://doi.org/<DOI> ???)
    ```
  - `write_report(path, build_report_rows(papers, features, ratings))`
  - `write_issues_csv(path, issues)`, by stage, then by line number
- Columns of `report.csv`
  ([`R18`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r18-report-csv)):

  | Column               | Content                                                                                               |
  | :------------------- | :---------------------------------------------------------------------------------------------------- |
  | `reference`          | The reference of [`R2`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r2-reference-format) |
  | `paper_quality`      | Rating 1 to 5, or `unknown`                                                                           |
  | `performance`        | Free text, or `unknown`                                                                               |
  | `recency`            | Publication year                                                                                      |
  | `asset_class`        | Free text, or `unknown`                                                                               |
  | `theoretical_domain` | Free text, or `unknown`                                                                               |
  | `mechanism`          | Free text, or `unknown`                                                                               |
  | `page_length_score`  | 1 to 5, or `unknown`                                                                                  |
  | `affiliation_score`  | 1 to 5, or `unknown`                                                                                  |
  | `citations_score`    | 1 to 5, or `unknown`                                                                                  |
  | `base_name`          | `<BASE>`, to open the PDF and the features file                                                       |

- Keys of an item of the papers file `01-resolve.paper_list.json`: `reference`, `year`,
  `authors`, `title`, `doi`, `arxiv_id`, `s2_paper_id`, `source`, `base_name`,
  `download_inputs`, `line_nos`, `key`, `aliases`
  - A list (e.g., `authors`) is a JSON array, so an item can hold any char
  - The file has the key `papers` and the `schema_version`
  - The input CSV has one paper per row and no header needed. A header with a
    column `input` is also accepted
- Columns of `issues.csv`
  ([`R19`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r19-issues-csv)):
  `line_no`, `input`, `base_name`, `stage`, `status`, `reason`, `candidates` (joined
  by `|`)
  - `status` is one of `unresolved`, `ambiguous`, `no_download_link`,
    `download_failed`, `conversion_failed`, `extraction_failed`, `rating_failed`,
    `rating_missing`
  - `stage` is one of `resolve`, `download`, `extract`, `rate`, in this order
- Shape of a features file (values are illustrative):
  ```json
  {
    "schema_version": 2,
    "base_name": "2020.Cohen_et_al.Lazy_Prices",
    "features": {
      "performance": {
        "value": "Sharpe 1.4, out of sample, 2005 to 2020",
        "evidence": {"quote": "...", "location": "Table 4, p. 21", "verified": true}
      },
      "recency": {
        "value": "2020",
        "evidence": {"quote": "2020", "location": "Semantic Scholar", "verified": true}
      }
    },
    "facts": {"sharpe_ratios": [], "sample_periods": [], "...": "..."},
    "affiliations": [
      {
        "author": "Lauren Cohen", "institution": "Harvard University",
        "kind": "university", "evidence": {"quote": "...", "verified": true}
      }
    ],
    "n_pages": 41,
    "provenance": {"model": "...", "prompt_sha1": "...", "cost_usd": 0.04}
  }
  ```
- Shape of a rating file (values are illustrative):
  ```json
  {
    "schema_version": 2,
    "rating": 4,
    "page_length": {"name": "page_length", "value": "41 pages", "score": 5},
    "affiliation": {"name": "affiliation", "value": "Harvard University", "score": 3},
    "citations": {
      "name": "citations",
      "value": "512 (Semantic Scholar, 2026-10-28)", "score": 4, "evidence": null
    }
  }
  ```

## Configuration, Interfaces, and Known Limits

- Configuration: `_SCHEMA_VERSION = 2` for the JSON files, the papers file too; CSV in UTF-8, with
  `csv.QUOTE_MINIMAL`, and a BOM at the start of a file that is read is skipped
- Interfaces:
  ```python
  def read_input_csv(path: str) -> List[Tuple[int, str]]: ...
  def write_papers(path: str, papers: List[epqtypes.Paper]) -> None: ...
  def read_papers(path: str) -> List[epqtypes.Paper]: ...
  def write_issues(path: str, issues: List[epqtypes.Issue]) -> None: ...
  def read_issues(path: str) -> List[epqtypes.Issue]: ...
  def read_issues_csv(path: str) -> List[epqtypes.Issue]: ...
  def write_features_file(path: str, features: epqtypes.PaperFeatures) -> None: ...
  def read_features_file(path: str) -> epqtypes.PaperFeatures: ...
  def write_rating_file(path: str, quality: epqtypes.QualityRating) -> None: ...
  def read_rating_file(path: str) -> epqtypes.QualityRating: ...
  def build_report_rows(
      papers: List[epqtypes.Paper],
      features: Dict[str, epqtypes.PaperFeatures],
      ratings: Dict[str, epqtypes.QualityRating],
  ) -> List[Dict[str, str]]: ...
  def write_report(path: str, rows: List[Dict[str, str]]) -> None: ...
  def write_issues_csv(path: str, issues: List[epqtypes.Issue]) -> None: ...
  def write_references(path: str, papers: List[epqtypes.Paper]) -> None: ...
  ```
- Known limits:
  - A papers file or an issues file with an old `schema_version` fails to read: run
    `resolve_papers.py` again
  - A features file with an old `schema_version` fails to read: `report_papers.py`
    records an issue that asks for `extract_features.py --force_extract`
  - A rating file with an old `schema_version` fails to read: `report_papers.py`
    records an issue that asks for the action `rate`
  - `report.csv` shows the values only: the evidence is in the features file
  - A CSV file has no schema version: a file with a missing column fails to read
  - The `candidates` cell of `04-report.issues.csv` joins the items with `|`, so an
    item must not hold `|`: the CSV is for a person, and no program reads it back
    except the tests

## Deliberately Not Built

- An HTML or spreadsheet view: the user sorts the CSV
  ([PRD Non-Goals](/research/Estimate_academic_paper_quality/docs/01-prd.md#non-goals))
- A merge of user edits: the CSV is written again on each run
