# Design: Resolver

## Goal

- Turn the lines of the input file into one deduped, sorted list of papers
  - Classify each line (PRD
    [`R1`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r1-input-file-format))
  - Match each line to exactly one paper of a bibliographic source, or mark it
    `unresolved` or `ambiguous` with its candidates
    ([`R3`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r3-bibliographic-source),
    [`R5`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r5-unresolved-or-ambiguous-line))
  - Merge the lines of the same paper
    ([`R6`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r6-duplicate-lines))
  - Build the reference, the base name, and the ordered download inputs of each paper
    ([`R2`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r2-reference-format),
    [`R4`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r4-download-link),
    [`R9`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r9-file-base-name))
  - Sort the papers in reverse chronological order
    ([`R7`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r7-reverse-chronological-order))
  - Write the papers and the issues as JSON in the output dir, and keep a copy of the
    input CSV there
    ([`D29`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d29-numbered-stage-files-in-the-output-dir),
    [`D31`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d31-json-for-the-intermediate-files))
- Where it fits: `resolve_papers.py` -> `resolver` -> `bib_sources`. The code of
  `resolver` lives in `resolve_papers.py`, with no module of its own (decision
  [`D28`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d28-a-module-with-one-caller-lives-in-that-script))
- Overview:
  [`research/Estimate_academic_paper_quality/docs/02-design.architecture.md`](/research/Estimate_academic_paper_quality/docs/02-design.architecture.md)
- Decisions:
  [`research/Estimate_academic_paper_quality/docs/03-decisions.md`](/research/Estimate_academic_paper_quality/docs/03-decisions.md)

## External Code

- `download_utils.detect_doi()` matches a DOI URL or a bare DOI, and
  `download_utils.get_ssrn_id()` matches an SSRN URL or an SSRN DOI
  `10.2139/ssrn.<id>`
- The download tool checks a local file first, then SSRN, then a DOI, then an arXiv
  ID, then a URL: `_parse_line()` keeps this order, so both classify a line the same
  way
- The arXiv regex of the tool, `\d{4}\.\d{4,5}`, also matches inside a DOI (e.g.,
  `10.1016/j.jfineco.2019.12345`): checking the DOI first avoids this
- The tool names a file with the private `_format_base_filename()`, which takes the
  last word of the first author (`Jackson, Jr.` gives `Jr.`) and keeps `.` and `,` in
  the title, against
  [`.claude/skills/references.rules.md`](/.claude/skills/references.rules.md)
- Move `_format_base_filename()` to `download_utils.format_base_filename()`, take the
  family name, drop suffixes like `Jr.` and `III`, and replace `.` `,` `'` with `_`
  ([`D7`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d7-the-pipeline-computes-the-base-name-with-a-public-helper))

## One Request End to End

- `resolve_papers.py` reads a CSV with no header needed: each row is one entry,
  numbered with its place after the header (if any), and `resolve_papers._read_input_lines()`
  calls `_parse_line()` for each row
  ([`D26`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d26-the-resolver-is-a-separate-executable-that-reads-and-writes-csv),
  whose CSV output
  [`D31`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d31-json-for-the-intermediate-files) replaces with JSON)
- `_main()` writes the files of the run in the output dir, with the names of
  `epq_paths`
  ([`D29`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d29-numbered-stage-files-in-the-output-dir),
  [`D31`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d31-json-for-the-intermediate-files)):

  | File                         | Writer                      | Content                            |
  | :--------------------------- | :-------------------------- | :--------------------------------- |
  | `00-paper_list.csv`          | `_copy_input()`             | Copy of the input CSV              |
  | `01-resolve.paper_list.json` | `epq_report.write_papers()` | The papers, newest first           |
  | `01-resolve.issues.json`     | `epq_report.write_issues()` | The unresolved and ambiguous lines |

  - `_copy_input()` runs first and overwrites an earlier copy, since a rerun can use
    a new list: it skips the copy if the input is already that file
  - The other executables read the papers file as the default of their `--input`
- `_parse_lines(raw_lines)` is for a markdown list: it first joins a bullet that is
  wrapped on several lines into one entry, numbered with its first line, then calls
  `_parse_line()`
  ([`D25`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d25-the-parser-joins-the-lines-of-a-wrapped-bullet)).
  The executable does not call it: a bullet list becomes a CSV first
- `_parse_line(line_no, text)`, the first match wins:

  | Kind        | Test                                                    | Key           |
  | :---------- | :------------------------------------------------------ | :------------ |
  | skip        | Empty, or starts with `#` or `//`                       | none          |
  | `local_pdf` | `os.path.isfile()` after `~` expansion, ends `.pdf`     | Absolute path |
  | `ssrn`      | `get_ssrn_id()` is not empty                            | SSRN id       |
  | `doi`       | `detect_doi()` is not `None`                            | DOI           |
  | `arxiv`     | `arxiv.org/abs/` or `/pdf/` URL, or a bare new-style id | arXiv id      |
  | `url`       | Starts with `http://` or `https://`                     | URL           |
  | `title`     | Anything else                                           | Title text    |

  - A `title` line ending with `(...)` gives the author hints: the text in the
    parentheses, split on `;` or `,` (format of
    [`research/Estimate_academic_paper_quality/paper_list.csv`](/research/Estimate_academic_paper_quality/paper_list.csv))
- `_lookup_candidates(input_line)`, by kind:

  | Kind        | Lookups                                                                                                 |
  | :---------- | :------------------------------------------------------------------------------------------------------ |
  | `arxiv`     | arXiv by id, Semantic Scholar `ARXIV:<id>`                                                              |
  | `doi`       | Semantic Scholar `DOI:<doi>`, Crossref by DOI                                                           |
  | `ssrn`      | Crossref and Semantic Scholar by DOI `10.2139/ssrn.<id>`                                                |
  | `url`       | HTML: `citation_doi` or `citation_title` meta tag, then as above; PDF: title of page 1, then as `title` |
  | `local_pdf` | `epq_fetcher.read_pdf_title()`, then as `title`                                                         |
  | `title`     | Semantic Scholar search (top 5), Crossref `query.bibliographic` (top 5)                                 |

- `_match_candidates(query, author_hints, candidates)`
  ([`D3`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d3-a-line-matches-when-one-distinct-paper-passes-the-title-test)):
  - Normalize the titles: ASCII, lowercase, no punctuation, single spaces
  - Similarity: `1.0` if equal, `0.95` if one is a prefix of the other (a partial
    title, or a missing subtitle), else `difflib.SequenceMatcher.ratio()`
  - Drop a candidate below `_MATCH_THRESHOLD = 0.9`
  - With author hints: drop a candidate that shares no last name with the hints
  - Group the rest by `_paper_key()`: one group gives a match; zero gives
    `unresolved`; two or more give `ambiguous`, unless exactly one group has
    similarity `1.0`
  - An id lookup (`arxiv`, `doi`, `ssrn`) that returns a record is a match with no
    similarity test
  - An `Issue` lists up to 3 candidates as references
- `_paper_key(record)`
  ([`D2`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d2-paper-identity-is-the-normalized-title-plus-the-first-author)):
  - The normalized title plus the last name of the first author
  - The DOI, the arXiv id, and the Semantic Scholar id are aliases of the key, so a
    preprint and its journal version merge
- `_build_paper(group, input_line)`
  ([`D1`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d1-semantic-scholar-record-is-the-canonical-record),
  [`D5`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d5-each-paper-keeps-an-ordered-list-of-download-inputs),
  [`D6`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d6-a-reference-with-no-download-link-ends-with--)):
  - Canonical record: the Semantic Scholar record, else the Crossref record of type
    `journal-article`, else any Crossref record, else the arXiv record
  - Year, first author, and title come only from the canonical record
    ([`R3`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r3-bibliographic-source))
  - Download inputs, in order, each kept only if known:
    1. The local PDF of the line
    2. The URL of the line
    3. `https://arxiv.org/pdf/<id>`
    4. The `openAccessPdf` of Semantic Scholar
    5. The `url_for_pdf` of Unpaywall, if `--email` is set
    6. The SSRN abstract URL, for a paper with an SSRN DOI
  - Reference: `<Year>, <Last name> [et al.], "<Title>" (<Link>)`, where the link is
    the first public download input
  - With no public download input: `(<DOI URL> ???)`, or `(???)` with no DOI
    ([`R4`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r4-download-link))
- A lookup calls the sources of the kind one by one (e.g., Semantic Scholar and
  Crossref for a title). A source that fails is skipped, and the reason of an
  unresolved line says that a source failed; if every source fails, the error is
  raised, so that an outage is not shown as an unknown paper
- A `title` line that is a path to a `.pdf` file that does not exist is
  `unresolved`, with the reason `the file '<path>' does not exist`
- `_merge_papers(papers)`: lines with the same `_paper_key()` give one `Paper` that
  keeps all the line numbers and the union of the download inputs
  ([`R6`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r6-duplicate-lines))
- `_sort_papers(papers)`: year down, then last name of the first author, then title
  ([`R7`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r7-reverse-chronological-order))

## Configuration, Interfaces, and Known Limits

- Configuration: `_MATCH_THRESHOLD = 0.9`, `_MAX_CANDIDATES = 5`
- Command line:
  - `--input` (required): the input CSV
  - `--output_dir` (required): the dir of all the outputs and of the state of the
    run
    - The script writes several files, so it takes a dir and infers the names: it
      has no `--output`
      ([`D30`](/research/Estimate_academic_paper_quality/docs/03-decisions.md#d30-output_dir-for-several-files-and-output-for-one))
  - `--cache_dir`: default `<output_dir>/state/cache`
  - `--email`, `--dry_run`, and the `--cache_mode` switch of `hcache_simple`
  - Flag abbreviations are off (`allow_abbrev=False`), so `--output` fails instead
    of matching `--output_dir`
- Interfaces:
  ```python
  def _parse_line(line_no: int, text: str) -> Optional[epqtypes.InputLine]: ...

  def _parse_lines(raw_lines: List[str]) -> List[epqtypes.InputLine]: ...

  def _resolve_line(
      input_line: epqtypes.InputLine, sources: epqbibso.BibSources
  ) -> epqtypes.ResolveResult:
      """
      :return: one paper, or one issue; a lookup error is raised, and the
          loop of `resolve_papers._resolve()` catches it per line
      """

  def _finalize_papers(papers: List[epqtypes.Paper]) -> List[epqtypes.Paper]:
      """
      :return: papers merged by `_merge_papers()` and sorted by `_sort_papers()`
      """

  def _resolve_lines(
      raw_lines: List[str], sources: epqbibso.BibSources
  ) -> epqtypes.ResolveResult:
      """
      :return: deduped, sorted papers and the issues of the lines; it does not
          catch the error of a lookup
      """
  ```
- Known limits:
  - Old-style arXiv ids (e.g., `hep-th/9901001`) are not detected: they resolve as
    `title` only if the text has a title
  - A `url` line that points to a direct PDF is downloaded once to read its title,
    and once more by the download tool
  - A title of page 1 is the largest text of the page: a PDF with a cover page (e.g.,
    a journal cover) can give a wrong title, which then often stays `unresolved`

## Deliberately Not Built

- Search by authors only, or by a free-text description
- An LLM to clean the lines: the lookup sources and the similarity test are enough,
  and
  [`R3`](/research/Estimate_academic_paper_quality/docs/01-prd.md#r3-bibliographic-source)
  forbids the LLM as a source of facts
