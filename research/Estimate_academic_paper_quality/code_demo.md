# Code Demo: `research/Estimate_academic_paper_quality`

- Generated by `.claude/skills/review.create_demo/SKILL.md`
- Paths are from the repo root, so that you can run the commands directly
- The demo takes about 30 mins

# What the Tool Does

- Turns a list of academic papers into a JSON report that rates each paper from 1 to
  5, to pick the next papers to replicate
- Input: a CSV with one paper per row, as a title, link, DOI, or local PDF, e.g.,
  `research/Estimate_academic_paper_quality/paper_list.short.csv` (5 rows)
- Output: one file per stage and one set of files per paper, in `./run_demo`

# Run the Demo

- Needs: internet, a browser for the SSRN papers, and an LLM
- Costs: LLM calls
- Time: 30 mins
- Run the dry run first: it shows the command of each stage, and needs no internet,
  no LLM, and no browser
  ```bash
  > research/Estimate_academic_paper_quality/estimate_paper_quality.py \
      --input research/Estimate_academic_paper_quality/paper_list.short.csv \
      --output_dir ./run_demo \
      --dry_run
  ```
- Run the demo from the repo root. The script adds the repo root and `helpers_root`
  to `PYTHONPATH` for the stages, so no setup is needed:
  ```bash
  > research/Estimate_academic_paper_quality/estimate_paper_quality.py \
      --input research/Estimate_academic_paper_quality/paper_list.short.csv \
      --output_dir ./run_demo
  ```

# What Is Generated

- The demo writes its files in `./run_demo`, named `NN-<stage>.<what>.<ext>`: `NN` is
  the order of the stage, and `<BASE>` is the name of a paper
  ```text
  ./run_demo/
      00-paper_list.csv
      01-resolve.paper_list.json
      01-resolve.issues.json
      01-resolve.summary.txt
      02-download.issues.json
      02-download.summary.txt
      03-extract.issues.json
      03-extract.summary.txt
      04-rate.issues.json
      04-rate.summary.txt
      04-report.report.json
      04-report.references.md
      04-report.summary.txt
      papers/
          <BASE>.pdf
          <BASE>.md
          <BASE>.features.json
          <BASE>.rating.json
      state/
          cache/
          logs/
  ```
- The files:

  | File                          | Written by (stage)    | Content                                                  |
  | :---------------------------- | :-------------------- | :------------------------------------------------------- |
  | `00-paper_list.csv`           | `resolve`             | Copy of the input CSV                                    |
  | `01-resolve.paper_list.json`  | `resolve`             | The resolved papers, each with authors, DOI, `reference` |
  | `*.issues.json`               | each stage            | The papers that failed in the stage, with status, reason |
  | `*.summary.txt`               | each stage            | Counts of the stage, and the output files that it wrote  |
  | `papers/<BASE>.pdf`, `.md`    | `download`            | The paper and its markdown                               |
  | `papers/<BASE>.features.json` | `extract`             | The features of the paper, each with a quote as evidence |
  | `papers/<BASE>.rating.json`   | `rate`                | The rating from 1 to 5, and the signals behind it        |
  | `04-report.report.json`       | `report`              | One row per paper or unresolved line, with its issue     |
  | `04-report.references.md`     | `report`              | One reference line per resolved paper                    |
  | `state/cache/`                | `resolve`, `report`   | The cache of the lookup answers                          |
  | `state/logs/`                 | `download`            | The log of the download tool for each paper              |

- The rating of a paper comes from three signals: page length, affiliation, and
  citations
  - Each signal has a value, a score, and an evidence quote when the paper gives one
  - A signal with no data is `unknown`, e.g., the citations of a paper that Semantic
    Scholar does not have

# Example Result

- A past run of the demo gave these results:

  | Stage      | Papers in | Done | Failed | Issues                        |
  | :--------- | --------: | ---: | -----: | :---------------------------- |
  | `resolve`  |         5 |    5 |      0 | 0                             |
  | `download` |         5 |    3 |      2 | 2 `no_download_link`          |
  | `extract`  |         5 |    3 |      0 | 0 (2 skipped for no input)    |
  | `rate`     |         5 |    3 |      0 | 0 (2 skipped for no input)    |
  | `report`   |         5 |    3 |      2 | 2 `download.no_download_link` |

- The 3 rated papers got the ratings 3, 4, and 5, e.g.,
  `papers/2018.Bekaert_et_al.Good_Carry_Bad_Carry.rating.json` has the rating 5, from
  the page length score 5 (77 pages), the affiliation score 4, and no citations
- The numbers can change with the internet and the LLM, but the files do not

# Check the Output

- Read each `./run_demo/NN-<stage>.summary.txt`: it shows the counts of its stage
- Check that each failed paper is in the issues file of the same stage
- Compare `paper_quality` of one paper in `./run_demo/04-report.report.json` with
  `rating` in the `.rating.json` of the same paper
- Run the same command again: each stage skips the finished work, and the summary
  says so
