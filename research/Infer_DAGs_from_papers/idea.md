## Core Idea

- Adapt the two-phase DMCD workflow (LLM semantic drafting, then statistical
  validation) to academic papers instead of datasets
  - DMCD proposes a draft DAG from variable metadata and audits it with
    conditional independence tests on observational data
  - Here the input is the text of a paper: extract the association
    relationships that the paper suggests, and turn them into a DAG
- Build the DAG of each paper with the workflow in
  `papers/Causal_Analysis_for_Finance/notes.slides.md` (Theory Store): extract
  claims, normalize variables, create the DAG, merge DAGs, reduce the DAG
- Implement the workflow in the separate project `research/Infer_DAGs_from_papers/`
  - Reuse the pipeline in `research/Estimate_academic_paper_quality/` that fetches,
    extracts features from, and rates papers
  - Read the markdown of each paper from the output dir of that pipeline
  - Import only its low-level modules (`epq_paths`, `epq_fetcher`, `epq_types`),
    never its executables, and never import back
- The open point is how much of the DMCD machinery transfers when the input is
  prose and not a table of variables with metadata

## Formalization

- Sketch only: DMCD notation adapted to a paper, to be refined during
  implementation
  - Paper $p$ yields a set of variables $V_p$ and a set of suggested
    association relationships $R_p \subseteq V_p \times V_p$
  - Draft DAG of the paper: $G_p^{draft} = (V_p, E_p^{draft})$ with
    $E_p^{draft} \subseteq R_p$ oriented to be acyclic
  - Merged graph across papers: $G = \text{merge}(\{G_p\})$ over canonical
    variable ids
  - Final graph: $G^{final} = \text{reduce}(G, D)$, where $D$ is the
    observational data mapped to the nodes
- Pseudocode of the workflow:
  ```
  for each paper p:
      claims_p = extract_associations(text_p)          # Phase I: semantic
      V_p, E_p = normalize_and_orient(claims_p)        # canonical ids, acyclic
  G = merge({(V_p, E_p)})                              # literature graph
  G_final = audit_with_ci_tests(G, D)                  # Phase II: statistical
  ```
- Differences vs DMCD to resolve:
  - The LLM reads paper text, not variable metadata
  - Phase II needs data mapped to the nodes, which a paper alone does not
    provide

## Key Examples

- **Same variable, different names** (from the Theory Store slides): _"monetary
  tightening"_, _"policy rate hike"_, and _"increase in the federal funds
  rate"_ map to one canonical id, so graphs from different papers can merge
- **Association in the paper, edge in the DAG** (illustrative): a paper reports
  that variable A is correlated with variable B and gives no direction; the
  workflow must either orient the edge from context or keep it as an
  unoriented association
- **Collider bias** (edge case from DMCD): two variables that are marginally
  independent but dependent after conditioning on a common effect must not get
  a direct edge, even if a statistical test flags the dependence
- **Cycles after merge** (illustrative failure mode): two papers state opposite
  directions between the same pair of variables, so the merged graph is not
  acyclic

## Research Topics

- **Association extraction**: how to extract the relationships suggested by a
  paper, stated or inferred, with sign, lag, and provenance
- **Variable normalization**: canonical ids and operators, so that the graphs of
  different papers can merge
- **Orientation and acyclicity**: how to turn associations into a DAG and
  resolve conflicts between papers
- **Statistical audit**: conditional independence tests with multiple testing
  control, as in DMCD Phase II
- **Reuse of `datamap`**: which parts of its graph builder, validator, and
  refiner apply to this workflow
