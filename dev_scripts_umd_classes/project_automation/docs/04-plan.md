# GitHub Project Automation Implementation Plan

- Generated by `.claude/skills/project.create_plan/SKILL.md`

## Goal

- Make GitHub apply and enforce the rules for issues, PRs, and GitHub Projects with
  templates, checks, and automations
- Background:
  - Issue [#803](https://github.com/gpsaggese/gpsaggese.github.io/issues/803)
  - The idea: [`idea.md`](/dev_scripts_umd_classes/project_automation/idea.md)
  - The requirements:
    [`01-prd.md`](/dev_scripts_umd_classes/project_automation/docs/01-prd.md)

## Plan Hierarchy

- This file: what to build and in which order
- [`07-progress.md`](/dev_scripts_umd_classes/project_automation/docs/07-progress.md):
  what is done and learned
- [`03-decisions.md`](/dev_scripts_umd_classes/project_automation/docs/03-decisions.md):
  why it is built this way
- `- [ ]` is an unmerged PR and `- [x]` is a merged PR

## Roadmap

- `v0.1`: one set of rules in the docs and a PR template
  - A contributor finds one rule for each convention, and every new PR starts with
    the standard description
  - [ ] `PR_D1`
  - [ ] `PR_D2`
  - [ ] `PR_D3`
  - [ ] `PR_D4`
  - [ ] `PR_T1`
- `v0.2`: PR checks that need only `GITHUB_TOKEN`
  - A PR with no linked issue, with unchecked boxes, or with a `helpers_root` pointer
    outside `helpers` `master` shows a failing check
  - [ ] `PR_C1`
  - [ ] `PR_C2`
  - [ ] `PR_C3`
- `v0.3`: board automation and issue checks that need `PROJECTS_TOKEN`
  - The issue card moves to `In progress` and `In review` with its PR
  - An issue with no project prefix, or in more than one project, is flagged
  - An issue closed as completed with unexplained unchecked boxes is reopened
  - [ ] `PR_B1`
  - [ ] `PR_C4`
  - [ ] `PR_C5`
- `v0.4`: a project template that carries all the conventions
  - Copying `Template` gives a project with our statuses, fields, views, and
    workflows, and the existing projects are synced with it
  - [ ] `PR_B2`
  - [ ] `PR_T2`
- Releases are cumulative: a version also needs the PRs of the versions before it

- **Owner and due date**: Harshit Gadge, 2026-11-21

### `PR_D2`: [ ] Write the design docs

- **Background**: the PRD and the components are agreed, but there is no design doc
- Write `docs/02-design.architecture.md` and one `docs/02.<N>-design.<component>.md`
  per component with `/architecture.write_design`
  - Components: rules docs, repo templates, rule checker, GitHub client, entry points
    and workflows, submodule guard, project sync

- **Unit tests**: none, docs only
- **Result**: each later PR has a design doc to follow
- **Owner and due date**: Harshit Gadge, 2026-11-24
- **Acceptance**: every requirement maps to a component; GP's OK on the design

### `PR_D3`: [ ] Unify the rules in the work-organization docs

- **Background**: the docs in `helpers_root/docs/work_organization/` disagree and
  point to things that no longer exist
  - `all.use_github.how_to_guide.md` says to move a task to `To Review`, while
    `all.github_projects_process.reference.md` lists `In Review` and its lean board
    has no review status
  - `all.github_projects_process.reference.md` points to the `cryptokaizen` org, the
    `cmamp` repo, and organization templates
  - The docs say not to use sub-issues, which GitHub made generally available in 2025
- This PR is in the `helpers` repo
- In `all.use_github.how_to_guide.md` and `all.github_projects_process.reference.md`:
  - Use one list of statuses, with `In review`
  - Use one closing rule, see
    [`D2`](/dev_scripts_umd_classes/project_automation/docs/03-decisions.md#d2-close-an-issue-only-from-the-pr-that-finishes-it)
  - State when to use a checkbox, a sub-issue, or a separate issue
  - Replace the steps with an organization template by "Make a copy" of `Template`,
    and add the step to re-create the auto-add workflow
  - Remove the links to `cryptokaizen` and `cmamp`
- In `all.asana_process.how_to_guide.md`, fix the pointer to `tutorials/Asana`, which
  does not exist in `helpers`
- **Unit tests**: none, docs only
- **Result**: every convention has one rule in one place
- **Owner and due date**: Harshit Gadge, 2026-11-25
- **Acceptance**: no doc in `docs/work_organization/` mentions `cryptokaizen`,
  `cmamp`, or `To Review`

### `PR_D4`: [ ] Align the Noesis meta-doc with the unified rules

- **Background**: `research/Noesis/docs/08-how_we_work.md` says to use `Fixes` and to
  override the helpers guide
- Point to the closing rule of `all.use_github.how_to_guide.md` instead of restating
  it
- Depends on `PR_D3`
- **Unit tests**: none, docs only
- **Result**: Noesis follows the same rules as every other project
- **Owner and due date**: Harshit Gadge, 2026-11-25
- **Acceptance**: the Noesis meta-doc has no closing rule of its own

### `PR_T1`: [ ] Add the PR template

- **Background**: `.github/` has only `workflows/`, so a new PR starts with an empty
  description
  - `helpers_root/.claude/templates/github_PR_description.template.md` already
    defines the sections and their limits for the agents
- Add `.github/pull_request_template.md`
  - First line: `Closes #N` or `Part of #N`
  - The sections and the limits of the agent template, see
    [`D7`](/dev_scripts_umd_classes/project_automation/docs/03-decisions.md#d7-reuse-the-pr-description-template-of-the-agents)
- **Unit tests**: none; open a test PR and check the description it starts with
- **Result**: every new PR starts with the standard description and the issue link
- **Owner and due date**: Harshit Gadge, 2026-11-25
- **Acceptance**: a new PR in the repo opens with the template

## v0.2: PR Checks

- `PR_C1`: [ ] Fail a PR that is not linked to an issue
  - Find the issue in `Closes #N`, then `Part of #N`, then the branch name
    `UmdTask<N>_...`
  - Unit tests on the parser with PR descriptions and branch names
- `PR_C2`: [ ] Fail a PR with unchecked boxes in its description, and warn on a long
  description
  - Same module as `PR_C1`
- `PR_C3`: [ ] Fail a PR that points `helpers_root` to a commit outside `helpers`
  `master`
  - Reuse the `merge-base --is-ancestor` test of
    `.github/workflows/update_helpers_submodule.yml`
  - Add the same check as a local git hook
