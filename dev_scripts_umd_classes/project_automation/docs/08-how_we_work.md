## Task Rule

- Execute only the tasks that are in the master plan
- Create the GitHub issue for a task before starting it
  - Start the title with `Process:`
- Post an ETA in the issue when you take the task, and update it when it changes
  - See "Sync-ups" in
    `helpers_root/docs/work_organization/all.team_collaboration.how_to_guide.md`
- Write `Part of #803` in the PRs of this project, and `Closes #<N>` for the issue of
  the PR
- Make a PR that changes a setting (e.g., a project workflow or a branch protection)
  list the setting for the owner to change

## AI Rule

- Skills to use in each step of the loop:
  `helpers_root/docs/tools/ai/all.ai_workflows.how_to_guide.md`
- Using AI is fine, but the author must be able to explain every line of the
  AI-written code

## Communication Rule

- GitHub for coding questions and code review
- The markdown docs in this dir for the decisions and the plan, with a link from
  GitHub
- Slack for quick pings
- Office hours for the rest

## Records Rule

- Keep every decision and communication in a non-ephemeral system
- Prefer markdown in the repo
- Never keep a decision only in Slack or in a GitHub comment
