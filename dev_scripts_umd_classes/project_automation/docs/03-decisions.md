# GitHub Project Automation Decisions

- Generated by `.claude/skills/architecture.write_design/SKILL.md`

## Placement

### `D1` (Keep the code and the docs in the main repo)

- **Decision**: put the docs, the Python modules, and the workflows of the project in
  `gpsaggese.github.io`, under `dev_scripts_umd_classes/project_automation/` and
  `.github/`
- **Why**: the issues, the project boards, and the PRs that the checks run on are in
  this repo, and the workflows must live in the repo whose PRs they check
  - Code in `helpers` would need a `helpers` PR and a second PR to move the
    `helpers_root` pointer for every change
- **Alternatives**: `helpers`, under `dev_scripts_helpers/github/`, so that other
  repos reuse the checks
  - Move the pure rule checker there if another repo needs it
- **Status**: proposed

## Rules

### `D2` (Close an issue only from the PR that finishes it)

- **Decision**: write `Closes #N` in the PR that finishes the issue and `Part of #N`
  in the other PRs of the issue
- **Why**: GitHub closes an issue when a PR that links it is merged into the default
  branch, with a closing keyword or with a link set by hand in the sidebar
  - `Part of #N` is ignored by GitHub and read by our checks
- **Alternatives**: `Related to #N`, which our checks could also read, but which
  reads as unrelated work
- **Status**: proposed

### `D3` (Keep only issues on the project boards)

- **Decision**: add issues to the boards, not PRs; a PR is visible from its issue
- **Why**: a PR card duplicates its issue card and doubles the size of the board
- **Alternatives**: add the PRs too, so that the built-in workflows on PR events work
  without our Action
- **Status**: proposed

### `D4` (Use a personal access token stored as `PROJECTS_TOKEN`)

- **Decision**: authenticate the board automation with a token that has only the
  `project` scope, stored as a repo secret
- **Why**: `GITHUB_TOKEN` is scoped to the repo and cannot access projects; GitHub
  recommends a personal access token for user projects and a GitHub App for
  organization projects
- **Alternatives**: a GitHub App, if the projects move to an organization
- **Status**: proposed

### `D5` (Run the board Action on `pull_request_target` and read only PR metadata)

- **Decision**: trigger the board Action with `pull_request_target`, and read only
  the number, the description, the branch name, and the draft status of the PR
- **Why**: `pull_request_target` runs the workflow of `master`, so it gets the secret
  also for PRs from forks
  - It is safe only if it never checks out or runs the code of the PR
- **Alternatives**: `pull_request`, which gets no secret for PRs from forks
- **Status**: proposed

### `D6` (Reopen an issue closed as completed with unexplained unchecked boxes)

- **Decision**: reopen the issue and comment with the list of the open boxes
  - Skip the issues closed as "not planned"
  - Accept a box that points to another issue (`-> moved to #N`) or gives a reason
    (`wontdo: <reason>`)
- **Why**: #803 asks to enforce the rule, and GitHub cannot block closing an issue
- **Alternatives**: comment and add a label without reopening
- **Status**: proposed

### `D7` (Reuse the PR description template of the agents)

- **Decision**: build `.github/pull_request_template.md` from
  `helpers_root/.claude/templates/github_PR_description.template.md`
- **Why**: humans and `/github.find_name_for_pr` write the same format with the same
  limits
- **Alternatives**: a shorter template for humans, which drifts from the agent one
- **Status**: proposed

## Code

### `D8` (Keep the rule checks in pure Python, called by thin workflows)

- **Decision**: write the rules (find the issue of a PR, count the open boxes, check
  the title prefix) as pure functions with no I/O, and keep the GitHub calls and the
  workflow files thin
- **Why**: follows `ARCH1.1` and `ARCH1.4` in
  `helpers_root/.claude/skills/architecture.rules.md`, so that unit tests check the
  rules with plain strings, without GitHub
- **Alternatives**: shell steps inside the workflow files, which cannot be unit
  tested
- **Status**: proposed
