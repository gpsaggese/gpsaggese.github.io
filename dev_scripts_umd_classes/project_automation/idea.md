## Core Idea

- The rules for issues, PRs, and GitHub Projects live in docs, and people and agents
  do not follow docs reliably
  - E.g., PR #875 was opened for issue #874 without a closing keyword, so the
    issue shows "No branches or pull requests"
  - E.g., only 1 of the 6 issues of the `Process` project has the `Process:` prefix
  - E.g., `helpers_root` pointed to a commit missing from `helpers`, which broke
    `git submodule update --init` (#874)
- Turn each rule into a template, a check, or an automation, so that GitHub applies
  or enforces it
  - A template applies a rule by default
  - A check fails a PR or flags an issue that breaks a rule, with a message that
    says how to fix it
  - An automation does the step instead of a person, e.g., moving a card
- The idea is non-obvious because the projects are owned by the user `gpsaggese`,
  not by an organization
  - Organization templates do not exist for user projects
  - `GITHUB_TOKEN` cannot access projects, so the board automation needs a token
    with the `project` scope

## Formalization

- Each rule maps to the cheapest mechanism that enforces it:
  ```text
  rule -> template      if a default is enough (e.g., PR description)
  rule -> check         if a PR or an issue can break it (e.g., missing issue link)
  rule -> automation    if a person repeats the same step (e.g., move a card)
  rule -> doc only      if none of the above applies
  ```
- A PR is linked to issue `N` if one of these holds, in this order:
  - Its description contains `Closes #N` (the GitHub closing keyword)
  - Its description contains `Part of #N` (our convention, ignored by GitHub)
  - Its branch name starts with `UmdTask<N>_`

## Key Examples

- **Three PRs for one issue**: PR 1 and PR 2 say `Part of #900` and the issue stays
  open; PR 3 says `Closes #900` and merging it closes the issue
- **Review queue**: a PR marked ready for review moves its issue card to `In review`,
  so GP sees the issues waiting for him in one view
- **Closed too early**: an issue closed as completed with an unchecked box is
  reopened with a comment, unless the box says `-> moved to #N` or
  `wontdo: <reason>`
- **Bad submodule pointer**: a PR that points `helpers_root` to a commit outside
  `helpers` `master` fails a check before it can be merged

## Implementation plan

- Milestone 1: one set of rules in the docs and a PR template
  - Unify the rules in the work-organization docs and add the PR template
  - A contributor finds one rule for each convention
- Milestone 2: PR checks that need only `GITHUB_TOKEN`
  - Fail a PR with no linked issue, with unchecked boxes, or with a bad submodule
    pointer
- Milestone 3: board automation and issue checks with a `project` token
  - Move the issue card with its PR, flag issues with no prefix, reopen issues
    closed with open boxes
- Milestone 4: a project template that carries all the conventions
  - Copying `Template` gives a project with our statuses, fields, views, and
    workflows
