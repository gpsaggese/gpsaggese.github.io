# Markdown Check and Clean Up Script

- Generated by `.claude/skills/research_idea.format/SKILL.md`

## Core Idea

- The rules for markdown files live in two files that agents and people read:
  - `.claude/skills/markdown.rules.md`
  - `.claude/skills/text.rules.md`
- Reading a rule does not mean following it, so files drift from the rules
- Build one script that checks a markdown file against the rules and fixes what it
  can safely fix
- Each rule is split into two parts:
  - **Check**: find where the rule is broken
  - **Fix**: change the text so the rule holds
- Each part is done by code or by an LLM, whichever is more reliable for that rule
  - Code is used when the rule is about a pattern of characters
  - An LLM is used when the rule is about meaning
- The idea is non-obvious because a rule often needs code for the check and an LLM
  for the fix
  - E.g., code finds every em-dash, but the right rewrite depends on the sentence

## Formalization

- Decision rule for each part of a rule:
  ```text
  check -> code         if a regex or a parser finds every case
  check -> LLM          if finding a case needs reading the meaning
  fix   -> code         if there is one correct replacement
  fix   -> LLM          if the replacement depends on the sentence
  fix   -> report only  if a fix needs new content (e.g., add an example)
  ```
- Invariant: the script never changes:
  - Fenced code blocks
  - Inline code in backticks
- Code fixes are applied to the file
- LLM fixes are proposed as a diff, and a human accepts or rejects each one

- Transforms, by class:

## Key Examples

- **Code check and code fix**: `` **`lint_text.py`** `` becomes `` `lint_text.py` ``
- **Code check and LLM fix**: code finds an em-dash in a bullet
  - The LLM proposes a colon, parentheses, or a new sub-bullet
  - A human accepts or rejects the proposal
- **LLM check and LLM fix**: a bullet chains 4 steps with commas and "and"
  - The LLM proposes a parent bullet with one child bullet per step
  - A human checks that the split keeps the meaning
  - The "They appear everywhere" example in `text.rules.md` shows a split that
    changes the meaning, so this fix is never applied without review
- **Invariant**: a period at the end of `> echo hi.` inside a `bash` block stays
